# Organisation pendant le run

***

Bonnes pratiques à suivre avant, pendant et après un run pour garder un suivi clair des tickets et des heures, et faciliter la communication avec les PM et les clients.

## Avant le run

### Mettre à jour son créneau

- Renseigner/mettre à jour son créneau de run dans [ClickUp](https://app.clickup.com/2525260/v/c/2d22c-52315)

## Pendant le run

### Centralisation des tickets

- **ClickUp** est le canal principal de centralisation des tickets : toute demande, même mineure, doit y être suivie
- Chaque demande d'un client, qu'elle arrive sur **Slack** ou ailleurs, doit faire l'objet d'un ticket créé dans ClickUp
- Chaque ticket doit être **bien tenu à jour** au fil du run (statut, avancement, remarques)

### Suivi des tickets

- Mettre **tout le détail** de ce qui a été fait dans le ticket correspondant
- Mettre à jour le **statut** du ticket à chaque étape
- Si des retours sur un ticket sont faits sur Slack, les **reporter dans le ticket** : l'objectif est d'avoir tout le récapitulatif directement visible en consultant le ticket, sans devoir remonter la conversation Slack

### Organisation du développement

- Ne pas hésiter à travailler sur des **branches différentes** dès qu'il y a une grosse feature à mettre en place, pour ne pas mélanger plusieurs sujets dans un même diff
- Lors d'une **mise en ligne**, ne pas hésiter à **dupliquer le thème** avant de publier, pour avoir un backup immédiatement disponible en cas de souci après la mise en prod

## À la fin du run

### Compte rendu (CR)

- Faire un compte rendu avec **tout le détail de chaque ticket** traité pendant le run
- Bien noter dans le CR les **heures passées hors run**, afin de :
  - les déduire du prochain run, ou
  - les faire facturer par un PM

### Transmission et clôture

- Transmettre le CR au **PM en charge** et/ou au **client**
- Mettre à jour son créneau de run dans [ClickUp](https://app.clickup.com/2525260/v/c/2d22c-52315) :
  - le passer en **achevé**
  - vérifier qu'il est bien à la **bonne date**

## Checklist récapitulative

### Avant le run
- [ ] Créneau de run à jour dans ClickUp

### Pendant le run
- [ ] Toute demande client (Slack ou autre) transformée en ticket ClickUp
- [ ] Tickets tenus à jour (statut + détail)
- [ ] Retours Slack reportés dans le ticket concerné
- [ ] Branches dédiées pour les grosses features
- [ ] Thème dupliqué avant chaque mise en ligne

### Fin de run
- [ ] CR rédigé avec le détail de chaque ticket
- [ ] Heures hors run notées dans le CR
- [ ] CR transmis au PM et/ou au client
- [ ] Créneau de run marqué comme achevé, à la bonne date
